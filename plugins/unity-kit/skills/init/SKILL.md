# unity-kit init

Target project: `$ARGUMENTS` if given, otherwise the current directory. It must contain `ProjectSettings/ProjectVersion.txt`; if not, stop and say it is not a Unity project root.

## 1. Read the project facts

| Placeholder | How to read it |
|---|---|
| `{{UNITY_VERSION}}` | `m_EditorVersion:` in `ProjectSettings/ProjectVersion.txt` |
| `{{RENDER_PIPELINE}}` | `Packages/manifest.json`: `com.unity.render-pipelines.universal` → URP, `com.unity.render-pipelines.high-definition` → HDRP. If neither, and `m_CustomRenderPipeline` in `ProjectSettings/GraphicsSettings.asset` is `{fileID: 0}`, → Built-in. Add the package version. |
| `{{DOMAIN_RELOAD}}` | `ProjectSettings/EditorSettings.asset`: **off** only when `m_EnterPlayModeOptionsEnabled: 1` and `m_EnterPlayModeOptions` has bit 1 set (`DisableDomainReload`). Otherwise **on**. Write the raw values too, e.g. `on (EnterPlayModeOptionsEnabled 1, options 0)`. |
| `{{ASMDEFS}}` | Every `*.asmdef` under `Assets/` (not `Packages/` or `Library/`): name and folder. If none, write `none (all code in Assembly-CSharp)`. |
| `{{TEST_ASMDEFS}}` | The asmdefs from the row above that reference `UnityEngine.TestRunner`, list `UNITY_INCLUDE_TESTS` in `defineConstraints`, or have `"optionalUnityReferences": ["TestAssemblies"]`. If none, write `none`. |

If a file is missing or a value can't be read, write `unknown (<reason>)`. Never guess.

## 2. Write CLAUDE.md

1. Take the template at the end of this skill and replace every `{{...}}` placeholder. It is inline so no file outside the project has to be read.
2. If the project has no `CLAUDE.md`, write it at the project root.
3. If `CLAUDE.md` already exists, do not overwrite it. Show the user the filled template and ask whether to append it as a section, write it to `CLAUDE.unity-kit.md` instead, or skip.

## 3. Report

Print the five facts in a short list and the path written. Then:

- If domain reload is **off** and any script under `Assets/` declares a `static` field or event, suggest running the `unity-kit:unity-reviewer` agent to check that each one is reset.
- If there are no asmdefs, mention it, but do not create any; that is the user's call.

## Template

````markdown
# Unity project notes for Claude

<!-- Generated by /unity-kit:init. Edit freely; re-running init will not overwrite this file. -->

## Project facts

- Unity version: {{UNITY_VERSION}}
- Render pipeline: {{RENDER_PIPELINE}}
- Enter Play Mode: domain reload {{DOMAIN_RELOAD}}
- Assembly definitions: {{ASMDEFS}}
- Test assemblies: {{TEST_ASMDEFS}}

## Rules

1. **Match the project's style.** Use the existing namespaces, assembly definitions and patterns. Put new code in the assembly that owns the feature. Ask before adding a new asmdef, a new pattern or a new package.
2. **Use APIs that exist in {{UNITY_VERSION}}.** If you are not sure an API exists in this version, or whether it is deprecated, check before using it. A compile error or obsolete warning from an API is a bug in your change.
3. **Never edit an existing `.meta` file.** Unity owns GUIDs and import settings.
4. **Move, rename or delete an asset together with its `.meta`.** A shell `mv`/`rm` that leaves the `.meta` behind breaks every reference to that asset. Prefer doing it in the Editor. Never write a `.meta` by hand; Unity creates it on import.
5. **Do not edit `Library/` or `Temp/`.** They are generated.
6. **Static state must be reset.** Every static field, static event and singleton gets a reset in a `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]` method. With domain reload off this is required; with it on, it keeps the option to turn reload off later.
7. **Done means it compiles.** After changing C# or asmdef files, the project must compile with zero errors. Use `/unity-kit:compile-fix`.
8. **Before a commit, run `/unity-kit:precommit`:** zero compile errors, no new warnings, every asset has its `.meta`, tests pass.

## Platform notes

No platform pack installed. Platform-specific rules (Quest, OpenXR, mobile) live in separate `unity-kit-<name>` packs; each pack adds its own section here.
````
